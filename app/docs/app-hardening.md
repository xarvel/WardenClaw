# App: security blockers before the first public build (2026-09-28)

Work log for the app security work before the first public build: personal values out of store builds, owner confirmation, a device-only key store, the bench gated to its own profile, screen protection, and `console.log` only in development. Scope: `app/` only.

The app was bilingual (Russian and English) before the first release; now it is English only. UI strings below are quoted as in `app/src/core/i18n/en.ts` where they still exist.

## Plan

1. B8: empty judge and gateway defaults in the code, `trash-put` on paths as a setting in the app, explicit empty `EXPO_PUBLIC_*` in `production` and `preview`, the scripts refuse to build those with non-empty values, personal values in `.env.local` (not sent to EAS).
2. B10: owner confirmation for every weakening, `biometricsSecurityLevel: "strong"`, fail-closed for roots and dangerous cards when the module fails, changing the model turns autopilot off, an "Autopilot is on" banner and an autopilot lifetime.
3. B11: SecureStore only `THIS_DEVICE_ONLY` (device key `WHEN_PASSCODE_SET_THIS_DEVICE_ONLY`), rewrite old entries, wipe on the first launch after install.
4. B12: benchmark and mock cards only in the `bench` build (build flag, lazy `require`), in release only the `feed` and `pair` links, a "TEST" badge on mock cards, their text is not sent to the judge.
5. B13: YubiKey text from the wardend status response, the card shows that a rule by score will not fire without a score.
6. P0-11: `FLAG_SECURE` on Android (config plugin), an overlay on iOS when `inactive`, the switch only in `bench`.
7. P0-12: `console.log` only in `__DEV__`, the benchmark log only in `bench`.
8. Checks: `tsc`, tests, EAS builds `bench` and `preview`, install on the Pixel.

## Journal privacy and the judge URL

Done 2026-09-28. First release flags were not touched. Commits `1d7f1cd`, `7bfb504`.

- H-6, the full plugin call in the journal. The "requested" entry (`addCard`) wrote the card's `raw`; for a plugin card that is the whole pending record with `call` (params up to 512 KiB, with the content of the files being written), and the plugin does not shorten `command` at all. Now `journalRaw` (`approvals.ts`): instead of `call` it writes `callOmitted: { paramsBytes, digestOk }` (the params size in UTF-8 bytes, as the plugin measures it, and whether the digest recomputed by the phone matched), `paramsPreview`, `command` and `filePath` are cut to 500 characters with "…(+N)", `digest` stays (it finds the call in the plugin journal on the gateway). wardend exec entries (a signed envelope) and gateway cards are written as before; other entries do not carry the call payload. The card in memory still holds `call`: the phone recomputes the digest from it.
- Old entries (before `1d7f1cd`) are not changed in the database: the hash chain rests on them. The journal screen shows the payload through `payloadView` (`journalText.ts`): for an old entry the same `callOmitted` with the params size instead of `raw.call`. Journal search still finds the call text in old entries; erasing it takes a chain recomputation, which is a separate decision.
- H-7, the judge URL. Under the URL field on "Mode" there is the `model.urlHint` line (also the field's `accessibilityHint`): everything the judge rates is sent to this address (the command with its arguments, working directory, host and listed variables, or the tool call); use a provider you trust or your own model. The tool call is named because `buildUserPrompt` sends its arguments too.
- H-4, backup. Android: `android.allowBackup: false` in `app.json`. Dependencies do not declare their own backup rules in their manifests, there is no merge conflict; `expo config --type introspect` gives `allowBackup="false"` on `<application>` and next to it the expo-secure-store rules (`fullBackupContent`, `dataExtractionRules`). In those rules `include` covers only shared prefs without `SecureStore`, so the journal database was not in Auto Backup before either; now cloud and adb backup are off entirely, and device-to-device transfer on Android 12+ keeps the secure-store rules. iOS: the `wardenclaw.db` database stays in `Documents/SQLite` (the expo-sqlite default directory); after opening it, `initJournal` sets `NSURLIsExcludedFromBackupKey` on that directory with the `excludeFromBackup` function of the `modules/wardenpush` module (it is always built, not behind a flag); the directory attribute covers the `-wal` and `-shm` files too. It is set on every start: a restore or a transfer can remove it. The database does not need to move. expo-file-system, expo-sqlite and expo-modules-core have no ready API for this.
- Android background service (after `ba440ff`): while the app is open, `bg.running` is checked against `watch.isRunning()` every 10 s, so "Mode" no longer says "Service running" after the service stopped by itself on a series of failures. The service is not restarted from there: that would be the failure loop again.
